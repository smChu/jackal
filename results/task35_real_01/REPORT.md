# Task 3-5 실제 GUI → Gazebo 연동 검증

실행 시각: 2026-10-25 16:46 KST. ROS 2 Humble / Gazebo Fortress / PyQt5 5.15.6 / Matplotlib 3.5.1.

## 검증 환경과 방법

사용 중인 시뮬레이션과 분리된 ROS 도메인 및 Gazebo partition에서 검증했습니다. `results/task34_real_02/runtime_world.sdf`의 기존 `walking_person` 한 명과 렌더링 카메라를 사용했습니다. 현재 빌드된 Actor Controller가 실제 Actor Visual의 WorldPose를 읽어 발행한 GT를 기록했습니다. 목표 데이터나 임의 데이터로 GT를 만들지 않았습니다.

실제 X 데스크톱에 Python UI를 열고 Qt 마우스 이벤트로 클릭·드래그했습니다. 다음 작업을 확인했습니다.

- CSV 없이 빈 메인 창 실행, 목표가 없을 때 Start 비활성화.
- 클릭과 드래그로 경로 생성, 4×4 m 범위 밖 입력 거부.
- 점 드래그 이동, 오른쪽 클릭 삭제, Undo/Redo.
- 표에서 좌표 수정, NaN 입력 거부.
- 편집 창 CSV 저장 및 메인 창 목표 CSV 저장 결과 일치.
- Use path / preview는 목표만 적용하고 Publisher를 실행하지 않음.
- 다시 편집 창을 열었을 때 원래 편집점과 설정 유지.
- Send to Gazebo로 전송 대기 시작, 재생 중 편집 잠금.
- 기존 Publisher 정상 종료, 실제 GT 이동 및 XY·시간별 X/Y·거리 오차 그래프 갱신.
- 목표·GT·실시간 비교 CSV와 메타데이터 저장. 실험 결과 폴더에 PNG 생성 없음.

추가 확인으로 시뮬레이션이 없는 별도 ROS 도메인에서 전송이 대기하고 GT 파일을 만들지 않는 것, Stop 후 편집이 다시 활성화되는 것, 한 사람의 경로를 교체해도 다른 ID의 목표 데이터가 보존되는 것을 확인했습니다. 기존 우회전 CSV 재생도 별도 Fortress 서버에서 정상 종료했고 실제 GT 117개를 수신했습니다. 직선·사각형·주기 사이의 꼭짓점·중복점에 대한 변환, 일정 속도, yaw 및 CSV 읽기 호환성도 확인했습니다. 이 확인용 코드는 저장소에 추가하지 않았습니다.

## 실제 이동 결과

마우스로 그린 뒤 좌표 표에서 보정한 경로는 `(-1.5,-1.5) → (-0.5,-1.5) → (-0.5,-0.5)`입니다. 수직 구간 중간의 편집점도 포함되어 있습니다. 경로 길이 2 m, 속도 0.5 m/s, 이동 시간 4 s, 기본 샘플 주기 20 Hz입니다. 꼭짓점 도착 시각을 추가하여 목표 CSV는 83개 샘플입니다.

| 항목 | 실제 결과 |
|---|---|
| Publisher 종료 코드 | 0 |
| 실제 원본 GT 관측 수 | 117 |
| 시간 정렬 후 비교 지점 수 | 201 |
| GT 보간 비교 지점 수 | 200 |
| 전체 재생 시간 범위 GT 확보 | True |
| 평균 위치 오차 | 약 0.002000 m |
| 최대 위치 오차 | 약 0.00200005 m |
| 비교 시작 GT XY | (-1.5, -1.5) m |
| 비교 종료 GT XY | (-0.5, -0.5020) m |

오차는 기본 Target 선형 보간과 GT 관측 사이 선형 보간을 사용하는 실시간 비교 격자 기준입니다. 임의 시간 오프셋 보정 없이 Publisher의 정확한 재생 시작 시각으로 정렬했습니다. 이 수치는 이번 짧은 경로와 시험 환경의 결과이며 다른 샘플링 주기·부하·경로에서 같은 오차를 보장하지 않습니다. `live_metrics.csv`와 `live_comparison.csv`에 원래 수치를 보존했습니다.
