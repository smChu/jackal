# Gazebo 방향과 GUI XY 보기 정렬 검증

2026-10-25 17:14 KST, ROS 2 Humble / Gazebo Fortress. 기존 사용자의 시뮬레이션과 분리한 ROS 도메인·Gazebo partition에서 기존 `walking_person` 한 명으로 검증했습니다. 테스트 소스와 화면 PNG는 이 폴더에 포함하지 않습니다.

## 확인한 원인과 변경

`clearpath_gz/launch/gz_sim.launch.py`가 로드하는 `clearpath_gz/config/gui.config`의 기본 카메라는 `-6 0 6 0 0.5 0`입니다. 수평으로 +X를 바라보며, 화면 오른쪽은 -Y이고 위쪽은 +X입니다. 기존 GUI는 +X 오른쪽·+Y 위쪽이었습니다. Controller의 World 좌표 계산을 바꾸지 않고 그리기·비교 화면과 마우스 역변환을 동일한 표시 회전으로 맞췄습니다.

## 실제 검증

- GUI 화면에서 World +X 점은 원점보다 위쪽, World +Y 점은 왼쪽에 표시됨을 픽셀 위치로 확인.
- 회전된 그리기 창에서 클릭·드래그·점 이동·삭제·Undo/Redo·좌표 입력·CSV 저장 확인.
- 0°, 90°, -90°, 180°, 35.7°의 보기 전환에서 목표 CSV 바이트, 목표 데이터와 실험 폴더가 그대로 유지되는 것을 확인.
- World→보기→World 왕복과 거리 보존 확인.
- 수정된 보기에서 생성한 2 m 경로를 GUI로 전송해 실제 Gazebo Actor가 이동하는 것을 실제 GT로 확인.
- Target과 실제 GT의 XY 표시에도 같은 회전을 적용하는 것을 확인. 시간별 X/Y 및 거리 오차는 World 데이터로 계산.

경로는 World `(-1.5,-1.5) → (-0.5,-1.5) → (-0.5,-0.5)`이며, 기본 보기에서는 위로 1 m 이동한 뒤 왼쪽으로 1 m 이동합니다. 속도 0.5 m/s, 시간 4 s, 기본 샘플링 20 Hz입니다.

## 범위와 제한

현재 Gazebo 기본 카메라 방향을 기준으로 한 2D 평면 표시입니다. 사용자가 카메라를 돌리면 보기 방향을 수동 조정합니다. 실제 GUI 카메라의 실시간 자세 자동 추적과 원근 투영 일치는 구현하지 않았습니다. 전체 Jackal의 센서·Teleop 동시 검증과 세 Actor 통합은 이번 검증에 포함하지 않았습니다. Controller, World 및 센서 설정은 수정하지 않았습니다.
